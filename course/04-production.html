Module 04

Building for Production

Understand what Vite does under the hood, shrink your bundle, and publish Deck to npm so anyone can npx deck and it just works.

Lesson 4.1

What Vite actually does

vitebundling

The dev server uses native ESM — no bundling. The production build uses Rollup to tree-shake, code-split, and output optimized chunks. You'll read your own build output and understand every file.

What you'll do
  • Run vite build and inspect what lands in dist/
  • Understand chunks, entry points, and hash naming
  • Read the Rollup chunk graph and see what imports what
  • Compare dev mode (ESM, no transform) vs prod mode (bundled, minified)
Lesson 4.2

Bundle analysis and optimization

performance

Find what's bloating your bundle. Deck ships Tabler Icons, Tiptap, and shadcn — some of those are bigger than they need to be. You'll measure, then cut.

What you'll do
  • Add rollup-plugin-visualizer and read the treemap
  • Identify the largest chunks and what's pulling them in
  • Lazy-load routes with React.lazy and dynamic imports
  • Drop unused icon imports and measure the difference
Lesson 4.3

The npm publish pipeline

npmpublishing

The package.json fields that actually matter: bin, files, engines, exports. You'll test-install locally before publishing anything.

What you'll do
  • Configure files to ship only what's needed (not your source)
  • Set engines to declare Node version requirements
  • Use npm pack to inspect exactly what would be published
  • Test with npm link in another directory — does it work?
Lesson 4.4

Ship a binary CLI

clidistribution

Right now Deck needs tsx to run the TypeScript CLI. Published packages need compiled JS. You'll set up the build chain so npx deck just works.

What you'll do
  • Compile cli.ts and server/ to JS with the right module format
  • Add the shebang (#!/usr/bin/env node) to the compiled output
  • Wire up bin in package.json pointing to the compiled file
  • Test the full flow: npm pack, install the tarball, run deck
