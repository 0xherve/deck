Module 06

Editor Polish

The details that make an editor feel right: editing any file, keyboard shortcuts that match muscle memory, and finding things fast.

Lesson 6.1

Make non-markdown files editable

editorfeature

Right now only markdown files can be edited. You'll wire up SourceEditor with save support for plain text, JSON, YAML, and code files.

What you'll do
  • Add an edit toggle to the non-markdown file view
  • Connect useAutoSave to SourceEditor for non-markdown files
  • Handle large files (don't load a 10MB log file into the editor)
  • Show a clear indicator for unsaved changes
Lesson 6.2

Keyboard shortcuts that feel native

uxa11y

Wire up Cmd+S for save, Cmd+P for file finder, Cmd+W for close tab. Learn how to intercept browser defaults without breaking accessibility.

What you'll do
  • Build a lightweight keyboard shortcut system (no library needed)
  • Prevent browser defaults (Cmd+S tries to save the webpage)
  • Handle Mac vs Linux key differences (Cmd vs Ctrl)
  • Build a quick file-open palette (Cmd+P)
Lesson 6.3

Search across files

featureserver

Build a grep-like search that runs server-side and streams results back. Render matches with context lines, just like VS Code's search panel.

What you'll do
  • Add a /api/search endpoint using grep or recursive file reading
  • Stream results with SSE so large repos don't block
  • Build the search UI: input, results list, click-to-navigate
  • Highlight matches in the file viewer when navigating from search
