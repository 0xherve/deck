Module 05

Theming System

Build a theming layer that lets users swap the entire look of Deck with a JSON file. You'll learn how VS Code themes work and build something similar, simpler.

Lesson 5.1

CSS custom properties as a design system

cssdesign

The foundation: a token layer of CSS variables (colors, spacing, radii, fonts) that one file can redefine. You'll extract Deck's current hardcoded styles into tokens.

What you'll do
  • Audit every color and spacing value in the current CSS
  • Define a token schema: --deck-bg, --deck-fg, --deck-accent, etc.
  • Replace all hardcoded values with token references
  • Build a dark theme by redefining tokens — same components, different values
Lesson 5.2

Loading external themes

architecture

A JSON file in ~/.deck/themes/ that maps token names to values. The server reads it, the client applies it at runtime. You'll handle validation so bad themes don't break the UI.

What you'll do
  • Design the theme JSON format (what tokens are required vs optional)
  • Add a server endpoint that reads and serves theme files
  • Apply theme tokens as CSS variables on the root element
  • Validate themes on load — fallback gracefully for missing tokens
Lesson 5.3

A theme API for contributors

api-designdocs

Document the token contract so others can create themes. Ship 2-3 built-in themes. Add a theme picker to the UI.

What you'll do
  • Write the theme spec: required tokens, optional tokens, naming convention
  • Create 2 built-in themes (light and a second dark variant)
  • Build a theme picker dropdown in the toolbar
  • Persist theme selection across sessions
