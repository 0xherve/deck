Module 07

Dev Practices

The habits that separate "it works on my machine" from "it works." TypeScript confidence, testing without ceremony, and a git workflow that scales from solo to team.

Lesson 7.1

TypeScript for real

typescript

Not the tutorial version. You'll turn on strict mode in Deck, fix every error that surfaces, and learn to read TypeScript errors as useful messages instead of walls of red.

What you'll do
  • Enable strict: true in tsconfig and see what breaks
  • Fix each error — learn the difference between type assertions, guards, and narrowing
  • Understand when generics help and when they're noise
  • Read a complex type error: find the actual mismatch buried in the stack
Lesson 7.2

Testing what matters

testing

One integration test per feature beats twenty unit tests of implementation details. You'll write tests for the server routes that actually catch real bugs.

What you'll do
  • Set up vitest (already compatible with your Vite config)
  • Write a test for /api/file that catches path traversal attempts
  • Write a test for /api/git-status against a real temp git repo
  • Learn what not to test: don't test React rendering, test behavior
Lesson 7.3

Git workflow for solo devs

gitworkflow

Feature branches, meaningful commit messages, and tags for releases. The minimum git workflow that keeps you sane and makes your history useful.

What you'll do
  • Set up a branching convention: feat/, fix/, chore/
  • Write commit messages that explain why, not what
  • Tag releases with semver and understand what each number means
  • Set up a basic pre-commit hook (typecheck before commit)
