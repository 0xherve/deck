Module 02

CLI Foundations

Turn Deck from a script you run into a proper CLI tool. These lessons cover everything from how Node processes arguments to managing multiple running servers.

Lesson 2.1

How CLIs actually work

nodecli

Before Commander abstracts it away, understand what's underneath. process.argv, exit codes, stdin/stdout as streams, and how signals (SIGINT, SIGTERM) let you clean up gracefully.

What you'll do
  • Write a tiny CLI from scratch with raw process.argv parsing
  • Handle SIGINT to shut down the server cleanly
  • Understand exit codes and when they matter
  • See what Commander gives you vs what it hides
Lesson 2.2

Port management

networkingcli

Build the "find next open port" logic so you can run multiple Deck instances for different projects. Learn about net.createServer, EADDRINUSE, and how to probe for open ports.

What you'll do
  • Write a findOpenPort(startPort) function
  • Understand why ports conflict and what EADDRINUSE means
  • Wire it into Deck's startup so it auto-increments on conflict
  • Print the actual port in the startup message
Lesson 2.3

Multi-project awareness

processstate

Track which projects are running on which ports. Evaluate three approaches: PID files, a small JSON state file in ~/.deck/, or querying the OS directly.

What you'll do
  • Design the state tracking approach (and understand the tradeoffs)
  • Implement deck list to show running instances
  • Handle stale state (what if a process crashed without cleanup)
  • Add deck stop [project] to kill a running instance
Lesson 2.4

Subcommands and help text

uxcommander

Good CLIs feel good. Add subcommands, useful error messages, and minimal color output. Learn how tools like git and npm structure their help.

What you'll do
  • Add deck open, deck stop, deck list subcommands
  • Write help text that actually helps (examples, not just flag descriptions)
  • Add minimal color to terminal output without a dependency
  • Handle unknown commands and typos gracefully
